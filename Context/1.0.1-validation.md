# WaveDeck 1.0.1 validation - 2026-11-19

Changes: Language directly below Theme on Windows and Linux; English and Português (Brasil), saved as `en` and `pt-BR`. Existing settings default to English. Saving switches the interface immediately; Cancel preserves the current language. English source strings key the shared embedded Portuguese catalog. Media metadata, paths, shortcut identifiers, playback modes and preset identifiers retain their values.

Validation:

- Both .NET 10 Release projects build with zero warnings and errors.
- Windows native tests: **66/66 passed**, including language migration/persistence, unchanged playback identifiers, unique catalog keys, matching valid format placeholders, English fallback, Unicode and unchanged media-title arguments.
- Focused WPF localization checks pass: selector placement and both choices; English-to-Portuguese and back; save/reload and Cancel; live preset/transport labels; unchanged playback, sound settings and a playing song titled `Settings`.
- Rendered OldSchool Portuguese player and Settings screenshots were inspected. Adjusted the playlist source header to fit and retained the selected preset's translated display while preserving its identifier.
- Evidence is local and ignored: `artifacts/1.0.1-validation/native/` and `artifacts/1.0.1-validation/localization-verified/`.
- The broader WPF suite passed its first 29 reported groups, then stopped at global-media-key registration because the original running player already owns the shortcuts. It did not complete in this environment. The focused language checks use an isolated profile with global keys disabled.
- Linux compilation passes. Native Linux UI/runtime was not retested; the previously registered Ubuntu WSL disk was unavailable. Compilation does not establish native Linux behavior.

Google sign-in research: Google's official desktop OAuth flow opens the system browser and requires registered client credentials. yt-dlp's official documentation states that YouTube OAuth login no longer works. This release translates the existing external-browser/session connection; it does not add OAuth, Gmail access or claim successful real-account authentication. Sources: https://developers.google.com/identity/protocols/oauth2/native-app and https://github.com/yt-dlp/yt-dlp/wiki/Extractors#logging-in-with-oauth.

The live player folders, listening process, preferences and account-session files were preserved. Packaging uses isolated staging, and the release workflow builds from the matching version tag. Account access, watch history, audible listening and behavior on other machines remain interactive checks.
