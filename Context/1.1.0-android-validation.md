## Signed APK smoke checks

The release APK installed and launched successfully on the same isolated emulator. Android's Share intent opened a real YouTube URL in WaveDeck, expanded the video's chapters and produced an active native media session with advancing audio. The final APK also used **Add music → Android document picker → Downloads** to select the generated 30-second `WaveDeck-validation.wav`. With the screen off, its platform media state was `PLAYING`, position 20,931 ms, and the playback service was foreground with type `mediaPlayback`; the notification had `sound=null` and `vibrate=null`.

After pausing and force-stopping only the emulator app, a cold launch restored the WAV queue paused. Explicit Play resumed it using the persisted document read permission. Screenshots, restored UI hierarchy and playback/service snapshots are under `artifacts/android-validation/release-final-home.png`, `release-ended-home.png`, `release-restored.xml`, `final-local-screen-off.txt`, `final-service.txt` and `final-restored-playback.txt`. No AndroidRuntime crash was reported in these signed-build smoke checks. The temporary emulator was stopped after validation.

## Scope and physical-phone acceptance

The APK supports local SAF files/folders, public YouTube and direct online audio. It provides a Media3 media foreground service, separate foreground download service, system media session, noisy-route pause and automatic audio focus. Source downloads retain encoded audio privately; desktop conversion, Google sessions/watch history, desktop visualizers and global desktop hotkeys are outside this Android build. Desktop playlists can retain online URLs; desktop absolute file paths need selecting again on Android.

The emulator has no audible output or physical P2/Bluetooth earbuds. The tests prove handling of the corresponding Android commands, not actual earbud firmware, analog disconnection, Bluetooth routing, phone calls, decoder availability on every phone or vendor battery restrictions. API 26/ARM devices are supported by the package configuration but were not run here. Network playback can still buffer, and anonymous YouTube access can be rejected for restricted videos or particular networks.

On the development phone, install the APK and verify local music plus a public YouTube playlist, lock the screen and wait through multiple transitions, then check wired and Bluetooth play/pause/next/previous, unplug/disconnect pause, incoming-call interruption/resumption and reopening the UI. Test idle playback for long enough to encounter that phone's battery policy. Do not commit or publish this unfinished development work before the application is accepted as working. Future APK updates require Android's installer confirmation and a matching development signer; no future-update installation was possible against the current published 1.0.2 desktop-only release.
